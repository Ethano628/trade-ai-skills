# 内容写作规矩和事实卡

## 一、事实卡（`ops/fact-cards.md`）

所有页面里的数字和说法只能来自事实卡。建站时有事实库的直接沿用并加"等级"。

| 编号 | 事实（英文页面用语） | 来源 | 确认人/日期 | 等级 | 可公开 | 已被哪些页面引用 |
|---|---|---|---|---|---|---|
| P01 | Standard material: SUS304; SUS316 on request | 规格表 v2 | 用户 / 日期 | A | 是 | /products/wall-rack.html |

**等级**
- **A**：有文件/检测报告/照片，可直接引用。
- **B**：用户明确确认，但没有文件，可写，避免绝对化。
- **C**：行业通识或公开标准（写清出处，如某标准编号），可写并注明。
- **D**：推断或道听途说——**不上页面**。

**更正规则**：事实更正时，事实卡和所有引用它的页面同一天改（"已被哪些页面引用"一列就是为此）。

## 二、写一页之前：简报

```markdown
- 目标词 / 意图 / 业务价值：
- 负责页面（新建 or 改写哪页）：
- 前 3 名和被 AI 引用的页面各放了什么，我们能比它们好在哪（至少 2 点）：
- 要回答的买家问题（来自 PAA、询盘、GSC 查询）：
- 用到的事实卡编号（缺的写"缺"）：
- 内链：链到哪些页 / 哪些页要链过来：
- CTA：
```

对标控制在半小时内：只看"放了什么、什么顺序"，不抄文字。

## 三、写法
1. **答案先行**：标题下第一段 40–60 个词直接回答主问题（AI 答案和精选摘要最爱这种段）。
2. **具体**：数字 + 单位 + 条件；"durable" → "1.2 mm SUS304, salt-spray tested [事实卡 Q03]"。
3. **结构**：H2 用买家会问的问题；规格、对比、条款用 HTML 表格；步骤用有序列表；FAQ 用问答。
4. **为买家写**：采购经理关心的是规格、合规、交期、起订量、定制、风险。少讲公司历史，多讲他能得到什么。
5. **自然用词**：目标词在 title、H1、首段、一个 H2、图片 alt 各出现一次即可；用同义说法覆盖相关词，不堆砌。
6. **原创证据**：每页至少一样别人没有的东西——实拍图、测试数据、真实问题的答案、对比表、视频。这是和 AI 批量内容拉开差距的关键。
7. **可引用**：写清出处（标准编号、检测机构）；作者/公司信息清楚。
8. **地道英文**：一个市场一套拼写；去掉中式套话。

## 四、改写老页（排 4–20 名的快赢）
1. 看 GSC 这页展示最多的 5–10 个查询，确认主词。
2. Title 和 H1 对准主词（title 里要有它，且比现在更有点击理由）。
3. 首段改成答案先行；补上查询里出现但页面没回答的问题（加 H2 或 FAQ）。
4. 补表格、实拍图、事实。
5. 从 2–3 个相关页加内链过来。
6. 记录改动日期，2–4 周后看这页展示、排名、点击是否变化。**一次只改一组变量。**

## 五、发布前检查（每页）
- [ ] 每个数字都标得出事实卡编号；没有 D 级
- [ ] 没有 No.1/leading/best、无证据认证、客户名、公开报价
- [ ] 一个 H1；title/description 唯一且符合长度
- [ ] 和现有页面不抢同一个目标词
- [ ] 至少 1 样原创证据
- [ ] 图片有 alt；AI 示意图标 Illustration
- [ ] FAQPage 结构化数据和页面问答一致
- [ ] 有 CTA，至少 2 条内链进、2 条内链出
- [ ] 新页加进 sitemap；发布后提交 GSC 请求编入索引、Bing 提交网址

## 六、AI 起稿的用法
AI 可以起稿和改写，但必须：只用事实卡里的事实、过上面的发布前检查、加原创证据。**不批量生成**只换关键词的相似页面；独特的买家问题用完就停，转去改老页和做站外。
